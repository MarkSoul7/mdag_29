# Issue 讨论提纲

以下三个议题用于发起仓库的第一次讨论。发布时在 GitHub 选择对应的 Issue 模板，
复制“标题”和“正文”即可。

---

## 议题一：是否需要 `mdag gc`？根集合如何确定

**建议标题**：`[Feature] 是否增加 mdag gc 命令？如何定义“根集合”`

**正文**：

```markdown
## 背景

当前所有对象平铺在 `data/<cid>.json`，删除文件或重新导入不会清理旧对象，
长期使用后目录会累积大量不可达对象。

## 讨论点

1. 内容寻址系统没有“文件名”，无法像传统文件系统那样按路径判断对象是否还在使用；
2. 是否引入“根集合”（roots.json）记录用户认可的根 CID，从根出发标记可达对象？
3. 未被任何根引用的对象直接删除，是否需要“保留期”（例如 7 天）防止误删？
4. gc 是否应该默认关闭、必须显式执行？

## 我的初步想法

- 增加 `mdag gc --roots roots.json`，只删除不可达对象；
- 默认 dry-run，输出将删除的对象数量与总大小；
- `--force` 才真正删除。

欢迎从“安全性”和“实现复杂度”两个角度提出意见。
```

## 议题二：把 List 分块接入 CLI

**建议标题**：`[Feature] 增加 add --chunk-size，把 List 分块暴露到命令行`

**正文**：

```markdown
## 背景

`importer.AddPathWithChunkSize` 已实现大文件分块（List 对象），但目前只有测试在调用，
CLI 的 `add` 仍然整文件存为单个 Blob。

## 讨论点

1. 参数形式：`mdag add --chunk-size 4096 <path>` 还是环境变量？
2. 分块大小默认值取多少？（4 KiB 便于演示，1 MiB 更贴近实际）
3. 目录导入时，是否对目录内每个文件都应用分块？
4. 分块后 `cat` 已支持拼接，`ls` 是否应显示 List 的子块？

## 影响

- 会改变导入结果的 CID（同一文件分块与不分块 CID 不同），需要在 README 说明；
- 不改变对象格式，向后兼容。
```

## 议题三：新手第一次运行最容易卡在哪里

**建议标题**：`[Question] 第一次运行 mdag 时，你在哪一步卡住了？`

**正文**：

```markdown
## 目的

收集真实的使用反馈，改进 README 的“快速开始”。

## 请回复

1. 你的操作系统与 Go 版本；
2. 卡住的步骤（构建 / add / resolve / cat / ls）；
3. 报错信息原文；
4. 你期望文档补充什么。

## 已知的两个坑

- Git Bash 会把 `/docs/report.txt` 改写成 Windows 路径，需要
  `export MSYS_NO_PATHCONV=1`；
- `data/` 相对当前工作目录，换目录运行会“找不到对象”。

如果还有别的坑，欢迎补充，我会更新 README 与 FAQ。
```
