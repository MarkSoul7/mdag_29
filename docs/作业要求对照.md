### （2）选择许可证、写好 README 与项目文档

**许可证**：MIT。

选择理由：

- 本项目是教学演示性质，希望同学可以自由阅读、复制、修改；
- MIT 只有一条实质约束（保留版权与许可声明），不限制商业使用，兼容性最好；
- 与 Go 生态主流项目（如许多官方库）一致，降低读者理解成本；
- 相比 Apache-2.0 省略专利条款与 NOTICE 要求，对几十行的教学项目属于过度设计；
- 相比 GPL，不要求衍生作品同样开源，符合作业“被同学参考”的场景。

### （3）分支管理：创建分支、合并分支、解决冲突

**分支模型**：简化 Git Flow。`main` 为稳定分支，功能/文档分支短期存在，
统一用 `git merge --no-ff` 合入，保留分支拓扑。

**已创建并合并的分支**：

**冲突**：两个分支在 README“获取与构建”一节的同一位置分别插入 Windows 与
Linux/macOS 说明，`git merge` 报 `CONFLICT (content): Merge conflict in README.md`。
解决方式是保留双方内容并确定顺序（Windows → Linux/macOS → 原句），删除冲突标记后
提交，合并提交有两个父提交 `a834dc5` 与 `bbe229c`。完整过程见
[分支管理与冲突处理](分支管理与冲突处理.md) 第四节。

### （5）根据华为“五看三定”分析项目

**方法**：“五看”看趋势、看市场、看竞争、看自己、看机会；“三定”定战略控制点、
定目标、定策略。

**本仓库分析**（全文见 [五看三定分析](五看三定分析.md)）：

| 维度 | 结论要点 |
|------|---------|
| 看行业/趋势 | 内容寻址存储（CAS）是 Git、IPFS、OCI 镜像的共同底座；云原生与 AI 数据管线扩大了对可验证存储的需求 |
| 看市场/客户 | 直接“客户”是课程同学与教师；真实需求是“能讲清楚原理、能跑起来、能验证”的教学样例 |
| 看竞争 | Git（工业级但对象模型复杂）、IPFS（完整但依赖网络与大量概念）、各类博客 demo（短小但缺测试与文档）；空档是“单机、零依赖、可验证、有测试”的教学实现 |
| 看自己 | 优势：对象模型完整、CID 确定性可验证、测试覆盖主要路径；劣势：无 GC、无分块 CLI、单机文件存储、无并发控制 |
| 看机会 | 作为区块链/分布式系统课程的第一课；作为 IPFS/Git 内部原理的对照实验；作为可扩展的教学骨架 |
| 定战略控制点 | “可解释 + 可验证”：每个 CID 都能手工复算，每个行为都有测试 |
| 定目标 | 三层：教学可用（当前）→ 功能完整（GC、分块 CLI）→ 可演示分布式（多节点同步） |
| 定策略 | 保持零第三方依赖；文档先行；测试锁定行为；小步提交与分支隔离；以 Issue 驱动路线图 |

**状态**：已完成（正文约 3300 字）。
